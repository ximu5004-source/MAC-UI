# MAC UI 4.0

Windows x64 local release, internally versioned `4.0.0`.

The user confirmed verification passed and authorized this local installer.
This release retains the existing MAC UI appearance and saved desktop layout.

- Desktop file icons omit hover operation/path hints and retain native Shell
  file menus. Recent selections use bounded, state-validated preparation.
- Office notifications add UIA and Toast snapshot fallback paths; notification
  collection continues if optional WinRT event registration fails.
- Genie receives Windows minimize/restore events in addition to Dock/caption
  input, supports 4K sources, and restores the user's native animation preference
  through an exact-process service custodian.
- Window-list native queries run outside shared collection locks. Standalone
  builds check that all required frontend entry points are embedded.

The local package includes the matching source snapshot, checksums and technical
verification records. No GitHub upload or automatic installation is performed.
Detailed capture, concurrency and native-menu measurement limits remain in the
technical documentation and package verification record.

## Desktop background menu compatibility revision

Build `desktop-menu-20261102-r2` addresses the reported case where desktop
background right-click shows no menu on another Windows 11 25H2 PC while file
menus still work. The original PC did not reproduce that failure.

- Locate the live Explorer desktop with an explicit `CSIDL_DESKTOP` variant.
- Keep the active desktop view's native background menu as the preferred path.
  If binding or querying that menu fails, request the native virtual desktop
  folder's background `IContextMenu` on the local STA and append the existing
  organizer submenu. This is the Shell namespace root, not a physical Desktop
  directory. View-specific commands are available only when supplied by Shell;
  unavailable view state must not reset the organizer's layout.
- Record stage, HRESULT, timing and refused foreground activation in the local
  application log. Dismissing a menu does not trigger a replacement menu.

The affected PC still needs to verify this revision. Local probes and packaging
checks do not establish cross-machine acceptance. Appearance, version `4.0.0`
and saved user configuration are retained.

### Complete background view and icon prewarming revision

Build `native-menu-prewarm-20261102-r3` replaces r2's folder-only compatibility
menu, which the affected PC could open but which omitted View, Sort and Refresh.
Its compatibility view is now a real, owned Windows DefView for the virtual
desktop, hosted by `IExplorerBrowser`. Windows supplies those menu commands;
their resulting native view state is bridged back to the organizer. The hidden
view does not persist Shell view state or change the live Explorer layout just
to initialize menu checkmarks. The working live desktop menu remains preferred.

An Explorer instance that has failed the live menu path reuses the owned view
instead of repeating that failing bind on every click. Background menus are
prepared after startup, preference changes and menu closure. Visible file icons
are prewarmed gradually with a bounded cache; direct interaction takes priority.
Prepared menus remain single-use, with file, clipboard, Shift and expiry checks.
No hover operation hints or custom Windows menu items are introduced.

The affected PC still needs to verify the new revision. Cold Shell extensions
and a native query already in progress can exceed the latency target; no hard
cross-machine timing guarantee is asserted.

### Restore Explorer ownership of blank desktop input

Build `native-menu-query-20261102-r4` restores the original product-polish
desktop input route. Native window regions include painted icons, organizer
boxes and controls; blank desktop pixels are holes through which Windows sends
the original mouse input directly to Explorer. The frontend no longer prewarms
or calls a background `IContextMenu` for blank desktop input. Organizer surfaces
retain the original organizer action menu, while file icons retain native Shell
file menus and their bounded prewarming.

This change follows the affected PC's logs: background `QueryContextMenu` calls
took 120–190 seconds and delayed a real click by 309 seconds. The user confirmed
that Explorer's own desktop menu opens immediately with desktop management off.
The service exited normally; no access-denied error established an elevation
requirement. No specific Shell extension is blamed by this evidence.

A read-only native mouse observer preserves custom icon marquee selection from
blank space. It never consumes or replays mouse input, checks the real Explorer
desktop target, coalesces movement and cancels stale gestures. Only a live,
completed selection can request keyboard focus; new input and an active native
menu invalidate that request. Only the transient marquee rectangle joins the
window region during a drag. No permanent fullscreen input region is restored.

The legacy background menu compatibility API also permits asynchronous verb
state and provides bounded slow-call wait-chain diagnostics. These diagnostics
do not terminate threads, disable Shell extensions or request administrator
rights. The original blank-input route does not depend on that API.

The affected PC must still verify the revision. User-supplied logs are excluded
from the source and installer artifacts.
